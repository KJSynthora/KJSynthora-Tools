Code Diff Guide

📅 June 2025 ⏱️ 6 min read ✍️ KJSynthora

How to Compare Code Files Online — Complete Guide 2025

Whether you're reviewing a pull request, debugging a regression, or comparing API responses, understanding code differences is a core developer skill. This guide covers how to use a code diff checker effectively, what the different views mean, and when to use each option.

What is a Code Diff?

A diff (short for difference) is a structured comparison of two text files that shows exactly which lines were added, removed, or changed. The standard diff format uses + to mark added lines and − to mark removed lines, with unchanged "context" lines shown without a prefix to give you surrounding context.

Most version control systems like Git use the unified diff format by default. When you run git diff or review a pull request on GitHub, you're reading a unified diff. Understanding how to read and generate diffs is essential for code review, debugging, and documentation.

Unified vs Split View — Which Should You Use?

  • Unified view: All changes shown in a single column with +/- prefixes. Better for reading long diffs, spotting the overall pattern of changes, and copying to clipboard or creating patch files.
  • Split view: Original on the left, modified on the right, aligned row by row. Better for comparing complex changes, understanding context, and reviewing structural differences like function signatures or class definitions.

For most code reviews, split view is more intuitive. For generating patch files or posting in GitHub issues, unified view is the standard format.

Understanding Char-Level Diff Highlighting

When a line is modified (deleted and immediately re-added), this tool performs character-level diff highlighting within those lines. The changed characters are highlighted with a darker background, making it trivial to spot small changes like a variable rename, a changed parameter, or a modified string value — without having to scan the entire line manually.

💡 Pro Tip: Use "Ignore whitespace" when comparing code that has been reformatted or re-indented. This filters out lines where only the leading/trailing whitespace changed, showing only semantically meaningful changes. Use "Ignore case" when comparing config files or SQL queries where case differences don't matter.

When to Use Context Lines

  • ±3 lines: Default. Shows 3 lines before and after each change. Best for most diffs — enough context to understand what changed without overwhelming noise.
  • ±5 lines: More context. Useful when changes involve function calls where you need to see the full function signature.
  • Full: Shows the entire file. Best when files are short or when you need to verify no other lines changed elsewhere in the file.

Exporting Diffs

Use the .patch export to save a standard unified diff file. This can be applied directly to a codebase using git apply patch.patch or patch -p1 < patch.patch. Use the HTML export for documentation, bug reports, or sharing with non-developers.

Frequently Asked Questions

How do I compare two code files online? ▼
Paste the original code in the left panel and the modified code in the right panel, then click ⚡ Compare. Added lines appear green, removed lines appear red, unchanged lines are shown in grey for context.
What programming languages are supported? ▼
The tool works with any plain text — JavaScript, TypeScript, Python, HTML, CSS, JSON, SQL, Java, C++, Go, Rust, Markdown and more. The language selector is used for labeling; the diff algorithm works on raw text.
What does the similarity score mean? ▼
The similarity score is the percentage of lines that are identical between the two files. 100% means the files are identical, 0% means completely different. It's calculated as (matching lines × 2) / (total lines in both files).
Can I upload files instead of pasting? ▼
Yes. Click the Upload button on either panel, or drag and drop files directly onto the editor areas. Files are processed entirely in your browser — nothing is sent to any server.
What is "Ignore whitespace" and when should I use it? ▼
When enabled, lines that differ only in leading/trailing whitespace or indentation are treated as identical. Use it when comparing reformatted or re-indented code to see only semantically meaningful changes.
Can I export the diff as a .patch file? ▼
Yes. Click "Export .patch" to download a standard unified diff file. This can be applied to a codebase using git apply or the patch command.
