What is SQL?

SQL (Structured Query Language) is the standard language for relational databases. It's used everywhere — e-commerce, banking, healthcare, analytics. Unlike programming languages where you describe how to get data, SQL lets you describe what you want — the database figures out the rest.

💡
Key InsightSQL is declarative — you state what you want, not how to get it. This makes SQL queries closer to plain English than most programming languages.

WHERE vs HAVING — Critical Difference

WHERE — Filters ROWS (before grouping)
  • Applied BEFORE GROUP BY
  • Cannot use aggregate functions
  • Filters individual rows
  • WHERE salary > 80000 ✅
  • WHERE AVG(salary) > 80000 ❌ ERROR
HAVING — Filters GROUPS (after grouping)
  • Applied AFTER GROUP BY
  • Can use aggregate functions
  • Filters whole groups
  • HAVING AVG(salary) > 80000 ✅
  • HAVING name = 'Alice' ❌ Wrong use
💡
SQL Execution OrderFROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. This order is why WHERE can't use aliases from SELECT, and why HAVING sees aggregate results.

JOIN Types Reference

INNER JOIN
Only matching rows from BOTH tables. Most common. Non-matching rows are excluded silently.
LEFT JOIN
ALL rows from left table + matching from right. NULLs where no match. + WHERE right IS NULL = anti-join.
RIGHT JOIN
All right + matching left. Rarely needed — always rewritable as LEFT JOIN by swapping table order.
FULL OUTER JOIN
All rows from BOTH tables with NULLs where no match. Not in MySQL — simulate with LEFT UNION RIGHT.
🎯
Interview Power Pattern: Anti-JoinLEFT JOIN + WHERE right_table.id IS NULL finds rows in Table A with NO match in Table B. Used for: customers with no orders, employees with no dept, products with no sales.

Window Functions

Window functions are what separate intermediate SQL from advanced SQL. They calculate across rows without collapsing them like GROUP BY does. ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD, and running totals — all live below.

RANK vs DENSE_RANK vs ROW_NUMBER

FunctionTies handled howGaps in rankingWhen to use
ROW_NUMBER()Each row gets unique numberNo gaps, always 1,2,3,4Pagination, deduplication
RANK()Ties get same rank, next skippedGaps: 1,2,2,4Sports rankings, competition
DENSE_RANK()Ties get same rank, no skipNo gaps: 1,2,2,3Most interview questions
⚠️
Common Interview TrapWhen the question says "find the Nth highest salary", use DENSE_RANK() not RANK(). With RANK(), tied values at rank 2 would skip rank 3 — your "3rd highest" query returns nothing when it should return data.

Indexes & Query Optimization

Understanding why queries are slow and how to fix them separates developers who write SQL from developers who write good SQL. This lesson covers indexes, EXPLAIN plans, and the top optimization rules used in production.

What Is an Index?

An index is like a book's index — instead of reading every page to find a topic, you look up the page directly. Without an index, your database scans every single row (full table scan). With the right index, it jumps directly to the data.

Top Optimization Rules

🚫
Avoid SELECT *
Name specific columns — reduces I/O, data transfer, and makes schema changes safer.
📌
Index WHERE Columns
Create indexes on columns used in WHERE, JOIN ON, and ORDER BY. Priority: high-cardinality columns.
🎯
Use EXISTS over IN
EXISTS stops at first match. IN materializes the full subquery. EXISTS wins on large datasets.
📊
Filter Early
Filter in WHERE before JOINs when possible. Fewer rows to join = much faster.
🔢
Avoid Functions on Indexed Cols
WHERE YEAR(date) = 2024 breaks index. Use WHERE date BETWEEN '2024-01-01' AND '2024-12-31' instead.
📄
LIMIT on Large Scans
Always add LIMIT when exploring large tables. Never run SELECT * on a table with millions of rows.
