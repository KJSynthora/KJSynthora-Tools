📗 Module 1 · Lesson 1

SQL SELECT & FROM

The SELECT statement is the foundation of all SQL. Every query you ever write starts here. By the end of this lesson you'll be able to retrieve data from any table, select specific columns, and understand the basic SQL structure.

What is SQL?

SQL (Structured Query Language) is the standard language for communicating with relational databases. It lets you store, retrieve, update, and delete data. SQL is used in virtually every application that stores data — from e-commerce to banking to healthcare.

💡
Key InsightSQL is not a programming language in the traditional sense — it's a query language. You describe what data you want, not how to get it. The database figures out the best way to retrieve it.

Your First SELECT Statement

The most basic SQL query selects all columns from a table:

SQL
SELECT * FROM employees;
emp_idnamedepartmentsalarycity
1AliceEngineering95000Mumbai
2BobMarketing72000Delhi
3CarolEngineering88000Bangalore
4DavidHR65000Mumbai

The * means "all columns". You can also select specific columns:

SQL
SELECT name, department, salary FROM employees;

Column Aliases with AS

You can rename columns in your output using AS:

SQL
SELECT name AS employee_name, salary AS annual_salary, department AS dept FROM employees;

DISTINCT — Remove Duplicates

To see only unique values in a column:

SQL
SELECT DISTINCT department FROM employees; -- Returns: Engineering, Marketing, HR
✅
Best PracticeAlways name specific columns instead of using SELECT *. It makes queries faster (less data transferred), more readable, and protects you when table structures change.
🧪 Quick Check: Which query selects only the name and salary columns?

WHERE Clause & Filtering

WHERE is how you filter rows — it's one of the most powerful and frequently used SQL clauses. You'll use it in almost every real query you ever write.

Basic WHERE Syntax

SQL
SELECT name, salary FROM employees WHERE department = 'Engineering';

Comparison Operators

OperatorMeaningExample
=Equal tosalary = 95000
!= or <>Not equaldept != 'HR'
>Greater thansalary > 80000
>=Greater or equalage >= 25
BETWEENRange (inclusive)salary BETWEEN 60000 AND 90000
INList of valuescity IN ('Mumbai','Delhi')
LIKEPattern matchname LIKE 'A%'
IS NULLMissing valuemanager_id IS NULL

AND / OR / NOT

SQL
-- AND: both conditions must be true SELECT * FROM employees WHERE department = 'Engineering' AND salary > 85000; -- OR: either condition is enough SELECT * FROM employees WHERE city = 'Mumbai' OR city = 'Bangalore'; -- Equivalent using IN (cleaner) SELECT * FROM employees WHERE city IN ('Mumbai', 'Bangalore');

LIKE — Pattern Matching

SQL
-- % matches zero or more characters WHERE name LIKE 'A%' -- starts with A WHERE name LIKE '%son' -- ends with son WHERE email LIKE '%@gmail%' -- contains @gmail -- _ matches exactly one character WHERE code LIKE 'IN_' -- IN + any one char: INA, INB...
⚠️
Performance WarningLIKE with a leading % (like '%gmail') cannot use an index and will scan the entire table. For large tables, consider full-text search instead.

📗 Module 1 · Lesson 3

ORDER BY & LIMIT

Sorting results and limiting how many rows come back are essential skills. ORDER BY and LIMIT are used in nearly every real-world query.

ORDER BY

SQL
-- Sort by salary highest to lowest SELECT name, salary FROM employees ORDER BY salary DESC; -- Sort alphabetically (ASC is default) SELECT name FROM employees ORDER BY name ASC; -- Multi-column sort SELECT department, name, salary FROM employees ORDER BY department ASC, salary DESC;

LIMIT / TOP

SQL
-- Top 5 highest paid employees SELECT name, salary FROM employees ORDER BY salary DESC LIMIT 5; -- MySQL, PostgreSQL, SQLite -- TOP 5 in SQL Server: SELECT TOP 5 ... -- ROWNUM in Oracle: WHERE ROWNUM <= 5 -- Pagination: skip first 10, get next 10 SELECT * FROM employees ORDER BY emp_id LIMIT 10 OFFSET 10;

📘 Module 2 · Lesson 4

GROUP BY & HAVING

GROUP BY lets you summarize millions of rows into grouped statistics. It's the foundation of reporting queries — department totals, category counts, average scores.

Aggregate Functions

FunctionDescriptionExample
COUNT(*)Count all rowsCOUNT(*) → 4
SUM(col)Total of valuesSUM(salary) → 320000
AVG(col)Average valueAVG(salary) → 80000
MAX(col)Highest valueMAX(salary) → 95000
MIN(col)Lowest valueMIN(salary) → 65000

GROUP BY

SQL
-- Average salary per department SELECT department, COUNT(*) AS num_employees, AVG(salary) AS avg_salary, MAX(salary) AS max_salary FROM employees GROUP BY department;

HAVING — Filter on Groups

SQL
-- Only show departments with avg salary > 80,000 SELECT department, AVG(salary) AS avg_sal FROM employees GROUP BY department HAVING AVG(salary) > 80000;
❌ WHERE (wrong for aggregates)
Filters individual rows before grouping. Cannot reference aggregate functions. Cannot use SUM(), COUNT() etc.
✅ HAVING (correct for aggregates)
Filters groups after GROUP BY. Can reference aggregate functions. Use when filtering on COUNT, SUM, AVG etc.

📘 Module 2 · Lesson 5

SQL JOINs — All Types

JOINs combine data from multiple tables. They are the most-tested SQL topic in interviews and the core skill for any real database work. Mastering them changes everything.

INNER JOIN — Only Matching Rows

SQL
SELECT e.name, d.department_name, d.location FROM employees e INNER JOIN departments d ON e.dept_id = d.dept_id; -- Only employees WITH a matching department returned

LEFT JOIN — All from Left + Matches

SQL
-- Find customers who NEVER placed an order SELECT c.name, o.order_id -- will be NULL if no order FROM customers c LEFT JOIN orders o ON c.customer_id = o.customer_id WHERE o.order_id IS NULL;

All JOIN Types at a Glance

INNER JOIN
Only rows with a match in BOTH tables. Most common. Use when you only want records that exist in both.
LEFT JOIN
All rows from LEFT table + matching from right. NULLs where no match. Use to find "orphan" records.
RIGHT JOIN
All rows from RIGHT table + matching from left. Rarely used — LEFT JOIN is preferred by reversing table order.
FULL OUTER JOIN
All rows from BOTH tables. NULLs where no match on either side. Use to find all unmatched records.

SELF JOIN

SQL
-- Find employees who earn more than their manager SELECT e.name AS employee, m.name AS manager, e.salary AS emp_salary, m.salary AS mgr_salary FROM employees e JOIN employees m ON e.manager_id = m.emp_id WHERE e.salary > m.salary;

📙 Module 3 · Lesson 6

Subqueries & CTEs

Subqueries and CTEs let you break complex multi-step problems into smaller, readable pieces. They're the difference between a query that's impossible to understand and one that reads like English.

Subquery in WHERE

SQL
-- Find employees earning above company average SELECT name, salary FROM employees WHERE salary > ( SELECT AVG(salary) FROM employees );

Common Table Expressions (WITH)

SQL
-- Calculate dept averages THEN use them WITH dept_avg AS ( SELECT department, AVG(salary) AS avg_sal FROM employees GROUP BY department ) SELECT e.name, e.salary, d.avg_sal FROM employees e JOIN dept_avg d ON e.department = d.department WHERE e.salary > d.avg_sal;
💡
When to use CTE vs SubqueryUse CTEs when the same subquery is referenced more than once, when readability matters, or when building a multi-step calculation. Use subqueries for simple one-off filters in WHERE or SELECT.

📙 Module 3 · Lesson 7

Window Functions

Window functions are the single topic that separates intermediate SQL users from advanced ones. They perform calculations across rows without collapsing the result set — like GROUP BY but without losing the detail rows.

ROW_NUMBER, RANK, DENSE_RANK

SQL
SELECT name, department, salary, ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num, RANK() OVER (ORDER BY salary DESC) AS rnk, DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rnk FROM employees; -- Ties at 2nd place (90,000): -- ROW_NUMBER: 1,2,3,4 (always unique) -- RANK: 1,2,2,4 (skips 3) -- DENSE_RANK: 1,2,2,3 (no skip)

PARTITION BY — Ranking Within Groups

SQL
-- Top 3 earners PER DEPARTMENT WITH ranked AS ( SELECT name, department, salary, DENSE_RANK() OVER ( PARTITION BY department ORDER BY salary DESC ) AS dept_rank FROM employees ) SELECT * FROM ranked WHERE dept_rank <= 3;

LAG & LEAD — Previous/Next Row

SQL
-- Month-over-month revenue change SELECT month, revenue, LAG(revenue) OVER (ORDER BY month) AS prev_month, revenue - LAG(revenue) OVER (ORDER BY month) AS change FROM monthly_sales;

📙 Module 3 · Lesson 8

Indexes & Query Optimization

Understanding why queries are slow and how to fix them is what separates a developer who writes SQL from one who writes good SQL. This module covers indexes, EXPLAIN plans, and practical optimization techniques.

What Is an Index?

An index is like the index at the back of a book — instead of scanning every page to find a topic, you look up the page number directly. Without an index, the database scans every single row (a "full table scan"). With an index on the right column, it jumps directly to the matching rows.

SQL
-- Create an index on the email column CREATE INDEX idx_users_email ON users(email); -- Composite index (for queries filtering by both) CREATE INDEX idx_orders_customer_date ON orders(customer_id, order_date);

Reading EXPLAIN

SQL
EXPLAIN SELECT * FROM users WHERE email = 'a@b.com'; -- Look for: -- type=ALL → full scan (BAD on large tables) -- type=ref → index used (GOOD) -- rows → estimated rows scanned (lower is better) -- key → which index was used

Top Optimization Rules

🚫
Avoid SELECT *
Select only the columns you need. Reduces I/O and memory significantly on wide tables.
📌
Index WHERE columns
Add indexes on columns you frequently filter, join, or sort on — especially high-cardinality columns.
🔗
Use EXISTS over IN
EXISTS short-circuits after finding one match. IN materializes the full subquery. EXISTS wins on large datasets.
📊
Filter Early
Apply WHERE conditions before JOINs when possible. Reduces the number of rows joined.
